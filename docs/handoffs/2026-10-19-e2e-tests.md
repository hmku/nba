# Handoff 2026-10-19 - end-to-end draft workflow tests (e2e-tests subagent, cloud session)

## What was accomplished
- New e2e tests that drive only the public `fantasy ...` CLI (typer CliRunner in-process, plus a real
  `python -m fantasy.cli draft watch` subprocess). They check the JSON keys and exit codes documented in
  `.claude/skills/live-draft`, `.claude/skills/agent-run` and `docs/runbooks/live_draft.md`, so they also
  check the concurrent tech-debt refactor of `src/fantasy/draft/cli.py`.
  - `tests/test_e2e_live_draft.py`: the skill's full rehearsal for a 12-team, 13-round 3RR mock from slot 1.
    Run start (live), lock, set-order, then opponents via `draft pick --source browser` and mine via
    recommend, prepare-pick and confirm-pick. One deliberate deviation checks `agrees_with_model=false`.
    At the end it asserts: 13-man roster, a feasible starting lineup (bipartite matching on
    `settings show` slots), board complete with no gaps, nothing left in `submitted`, decisions logged, and
    `run end` releases the locks. The fast variant stops at my pick #37; the full 156-pick draft is `slow`.
  - `tests/test_e2e_draft_failures.py`: dry_run refusal (exit 4 `DO_NOT_CLICK`), missing or foreign lock,
    no run id, duplicate prepare (exit 5/7), confirm-pick without evidence or with an unknown txn, failed then
    retry (`attempt: 2`), a pick that isn't mine (`my_picks`), a player already drafted, name ambiguity
    (exit 2 + `candidates`, `--force` → `unknown:`), gap warnings in board/recommend/prepare-pick,
    undo + re-record, out-of-order recording. It also checks that `recommend` is deterministic (two calls
    match after volatile fields are removed), both before the draft and mid-draft.
  - `tests/test_e2e_draft_watch.py`: watch subprocess. One recommendation per board change (undo counts as a
    change), none while idle, and it exits 0 with "draft complete for my slot". It also injects a transient DB
    error (generic SQLAlchemy `Connection.execute` patch).
  - `tests/test_e2e_ops.py`: lock exclusivity across runs, stale-run reaping (a reaped run's heartbeat
    exits 7), the policy matrix for {drop, add_drop, trade, lineup, draft_pick} × {dry_run, live} through
    `txn plan/check/mark` and approvals, a rejected approval, and a lineup with no lock.
  - `tests/test_e2e_publish_parity.py`: `publish --rest --dry-run` row counts equal the local DB counts. The
    real `publish --rest` path runs through a mocked `httpx.HTTPTransport`: every row is POSTed and the key
    never appears in the output. Board/`order` `my_picks` for slot 1 match `tests/fixtures/draft_order_parity.json`
    (3RR and custom cases).
- `pyproject.toml` [tool.pytest.ini_options]:
  - Added the `slow` marker; the default `pytest` run deselects it (`-m 'not slow'`), so use `pytest -m slow` for those tests.
  - Added `pythonpath = ["src"]`. In this container the editable install pointed at another agent's worktree
    (`.claude/worktrees/agent-…`), so `pytest` was testing that worktree's code instead of this checkout's.

## Bugs found (src NOT changed; strict xfail, so a fix turns them into XPASS failures until the marker is removed)
1. `test_e2e_live_draft.py::test_draft_status_complete_after_last_pick` (slow): `drafts.status` never
   becomes `complete` after pick 156 and stays `live`, because `store.set_draft_status` has no caller.
2. `test_e2e_draft_failures.py::test_pick_overall_zero_rejected`: `draft pick --overall 0` is treated as
   if `--overall` were not given (`overall or next_open`), so it silently records pick #1.
3. `test_e2e_draft_failures.py::test_pick_overall_out_of_range_is_json_usage_error[157|-1]`: an
   out-of-range `--overall` raises an uncaught `ValueError` traceback (exit 1, no JSON) instead of a JSON
   usage error (exit 2).
4. When this was written, `draft watch` died on the first transient DB error. Commit 2d88621 (landed
   during this session) added retry/backoff, and `test_watch_survives_a_transient_db_error` now passes
   against it. It would skip if that behaviour were removed.
