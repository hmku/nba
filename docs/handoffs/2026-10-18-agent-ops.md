## Contract other areas should use
- Draft agent: `run start --mode live` (only when authorised) → `lock acquire draft:<id>` →
  `txn plan draft_pick --payload '{"draft_id":..,"overall_pick":..,"player_id":..}'` →
  `txn mark submitted` → click → `txn mark verified --evidence ...` → `run decision draft_pick`.
- Python callers can import `fantasy.ops.{ledger,locks,transactions,approvals,policy}` directly.
- `fantasy status --json` keys: `as_of, db, runs{active,stale,stale_minutes}, locks,
  approvals_pending, txns_needing_reconciliation, txns_awaiting_approval, tasks_open{P0..P3},
  model_freshness[{kind,run_id,model_version,created_at,age_hours}], active_draft`.

## Notes / caveats
- Timestamps are written by the client in UTC (not DB `now()`), so lease expiry assumes hosts
  have roughly synced clocks.
- `add` (pure add) is treated as approval-required, same as unknown kinds (conservative).
- `fantasy publish` skips `locks`; tasks/transactions colliding on title/idempotency key with a
  different online row are skipped and reported. Running runs published from offline will show
  as stale online until reaped.
- The dashboard's approval route should set `status`, `decided_by`, `decided_at` only where
  `status='pending'` (same compare-and-set as `approvals.decide`).
- `fantasy task seed` has not been run against Supabase yet — run it once.
