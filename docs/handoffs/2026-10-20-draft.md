## Why the draft row "said live"
`drafts.status` is derived from the pick count (`store.status_for`: complete iff picks ≥ 156, and live after an undo from complete).
During the J. Butler III name fix, pick 155 had been undone (`unknown:j-butler-iii`), so when pick 156 (Ace Bailey) was recorded at
03:11:21 UTC the board held 155/156 and the row read `live`. Pick 155 was re-recorded as `jimmy-butler` at 03:11:28 UTC, and
`_sync_status` moved the row to `complete` (`updated_at` 03:11:28). So any reader in that 7 s window, or any snapshot taken before it
(for example a brief written while the draft was still running), saw `live`. The supported path to (re)compute it is
`fantasy draft board --draft-id nba.l.44495-2026` (idempotent heal). I ran it and it returned `complete`; no manual SQL was needed.
